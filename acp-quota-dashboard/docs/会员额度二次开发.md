# 会员额度展示（本地二次开发）

基于上游 `28ccc6745ec82139c684c3642637e93e00d800f2`，本地版本 `0.2.1-rc.4.1+quota.1`。

入口：插件 → ACP 适配器 → Google Antigravity 卡片 → 刷新额度。

显示订阅类型、模型组的五小时／周剩余额度、重置时间和本次读取时间。会话 token 用量和会员额度分别展示；未提供的值显示未知，失败保留上次结果与读取时间。只读取当前官方 CLI 账号，不聚合或自动轮换多个账号。

## 数据来源

使用官方 `agy --settings` 的临时状态行设置，通过 `statusLine` 回调接收 `quota` 与 `plan_tier`。只调用交互界面的 `/usage`，不发送模型请求、不修改用户 settings.json、不读取或转发 OAuth 凭据、不直接请求 Google 私有接口。

官方文档：https://antigravity.google/docs/cli/statusline

Python3 标准库 PTY 用于承载临时 CLI 会话；读取后关闭进程组并删除临时文件。仅设备所有者可查询。只返回额度、订阅类型和当前登录邮箱的白名单，排除提示词和凭据。邮箱仅向设备所有者展示。查询合并并限制频率，不后台轮询。支持 macOS／Linux，Windows 显示不支持。

依赖：Python3，已登录的官方 Antigravity CLI（实测 1.5.2），可访问 Google 服务的网络。命令路径沿用该 Agent 的可执行文件配置，环境变量沿用该 Agent 的显式配置。

## Codex 额度接入

Codex 与 Antigravity 共用输入栏额度仪表及设置卡片。通过官方 `codex app-server` 的 `account/read` 和 `account/rateLimits/read` 查询当前 ChatGPT 登录账号，不创建会话、不发送模型请求、不读取 OAuth 文件。参考：https://developers.openai.com/codex/app-server 。

官方 Codex CLI 默认从 Agent 环境 PATH 解析，可在 Agent 显式环境中通过 `CODEX_CLI_PATH` 指定绝对路径；沿用该 Agent 的 CODEX_HOME 等环境配置。ACP 启动命令可能是桥接器，因此不能直接当作官方 CLI 使用。API key 登录或服务未返回额度时显示读取失败，不虚构余额。显示实际额度窗口、剩余百分比和重置时间；不同 Agent 的并发查询与冷却独立。

本次仅源码与隔离构建验证，不代表当前运行插件已更新，也不代表真实账号或浏览器验收通过。

## 同一 ACP 内切换模型的容量兼容

当 Sol 切换为 Terra 等同一 ACP 路由内的模型时，当前 Harness 的原生压缩前置检查可能抛出 `MODEL_SWITCH_COMPACTION_FAILED`，原因为 ACP 未提供 `contextWindow`。即使会话内容很少，也会在实际 ACP 配置同步之前失败。

插件在公开 `agent/request` 请求链外增加兼容处理：仅当目标属于当前已注册 ACP、前后 provider 相同、模型确实变化、内部请求链已返回最终配置，且错误原因精确匹配该目标的容量缺失时，继续交给已有 ACP 配置同步逻辑。请求链和绑定校验只执行一次，不伪造上下文容量。原生模型、跨后端切换、绑定异常、其他压缩错误及取消信号继续按原有规则处理。

这是对当前宿主错误格式与监听器顺序的兼容，宿主升级后需重新验证。外部 Agent 对目标模型的接受结果仍以 ACP 配置同步为准。本次完成源码类型检查、针对性回归与隔离构建；未覆盖正在运行的插件，未进行浏览器或真实 Sol → Terra 会话验收。

## Harness 新版工具批次接口兼容（quota.4.1）

Harness 0.2.2-rc.1 的公开 `tools.execute` 接口接收 `calls` 批次，旧插件传入的单次 `callId/name/arguments` 会在批次规划阶段因缺失 `calls` 抛出 `ToolBatchExecutionError`，模型只能看到 `Tool batch execution failed`。这与会员额度读取无关；本机故障会话的五次工具调用均已通过 Guardian Review。

工具桥接通过新版公开能力 `selectExecutor` 选择单元素批次接口，将参数编码为原始 JSON 字符串，校验返回的调用 ID，并保留工具结果、附加上下文、拒绝、取消和结束轮次标记。旧宿主继续使用旧接口。接口异常不触发自动重试，以免重复执行。新版跨 MCP 请求保守串行，宿主批次内部仍经过原生执行器与审批流程；没有新增权限旁路。

本机已安装运行包的隔离验证复现了旧调用的底层错误 `Cannot read properties of undefined (reading 'map')`；修复后工具成功执行一次，拒绝与预先取消均未执行工具。相关单元与 MCP 桥接回归共 93 项通过。验证不发送模型请求，不消费 Codex 对话额度。未进行浏览器测试或真实 ACP 会话验收，当前运行插件需安装新包并重启后才能使用修复。

开发依赖和 `engines.dsh` 仍固定旧版精确目标；本次只验证上述工具接口在本机 0.2.2-rc.1 的兼容，不代表整个插件已完成新版宿主兼容认证。新包若触发版本检查，应仅允许该包版本与该宿主版本的精确例外。

## ACP 会话用量展示

输入框下方通过公开 `conversation.composer.dock` 插槽展示 Agent 实际上报的上下文占用、费用、token 总量及输入、输出、推理、缓存读写分类。轮末 `PromptResponse.usage` 单独保存为最新上报快照；下一轮未上报则清空，历史快照冷读取标注“上次 Agent 上报”。只保存已校验的非负整数，不保存 `_meta`。

ACP 的轮末 token 用量仍为草案，存在本轮与会话累计口径差异，因此不自动写入 DSH 累计 TokenUsage，也不推算缓存命中率、tok/s 或上下文占用。缺失字段不补零；上下文仅来自 `usage_update`，会员额度保持独立。

协议依据：https://github.com/agentclientprotocol/agent-client-protocol/blob/main/docs/rfds/end-turn-token-usage.mdx 。这次改动不保证所有 Agent 都会上报，需安装后检查真实响应；没有上报时不会生成虚假的统计。

### 实时输出速度

ACP 用量栏增加 `实时输出 ≈ 42.6 tok/s`，支持 Antigravity 的流式正文及推理文本。每 250 毫秒刷新最近三秒收到的文本增量；ASCII 每四字符约一 Token，其他 Unicode 字符约一 Token。该值是文本接收速度估算，受分批推送影响，不代表服务端精确生成速度，也不参与用量累计。初次加载只建立基线，结束或切换步骤后重置；无新文本三秒后隐藏。

底栏精简为上下文用量及实时输出速度；输入、输出总量、缓存、推理分类及费用不再展示。上报数据仍保留，过期状态仅在悬停提示中说明。

quota.4.8：文本变化立即刷新速度，定时刷新缩短至 100 毫秒，首批输出计入统计。任务结束后展示“本次平均”，按该任务已加载的正文与推理文本估算 Token 数除以任务起止总耗时（包含等待和工具调用）；不再随流式消息结束清空。历史窗口未完整加载时，该平均值仅涵盖已加载文本。

quota.4.9：运行期间速度项常驻，暂无统计显示“等待输出”，采样窗口空闲显示零速率。同会话、同 Agent 的空快照或上下文缺报保留最近值并标记“上次”，收到新值后恢复；首次无数据显示“待上报”，避免底栏条目反复消失。

quota.4.10：本次平均改为实时观测的各正文/推理块估算 Token 总数除以各块首末文本增量时间之和，块间工具调用和等待不参与统计。单次推送无法测量持续时间，不参与平均；刷新后未观测的历史任务显示“暂无统计”。此口径仍为客户端文本接收速度估算。

quota.4.11：修复平均速度依赖底栏组件内存的问题。旧实现只在页面运行态采样，切换会话、刷新或组件重建会丢失记录，末批文本与结束状态合并更新时也可能漏记。现在由后台在接收 ACP 正文和推理增量时采样，工具及消息分段间隔不计时，子会话通知不计入主会话；按当前任务轮次汇总，并随终态会话快照保存。刷新、切换会话和重新启动后可读取最近任务的统计；新任务重新计数，不沿用上一轮速度。估算只保留 Token 数量和时长，不额外保存正文。

旧任务没有后台采样时显示“本次平均：缺少采样”，无法从最终文本恢复历史接收时间；整段只收到一次、没有可测时长时显示“本次平均：无可测输出时长”。该值仍是文本接收速度估算，不是计费 Token 消耗，也不会用包含工具等待的任务总耗时代替输出时长。新逻辑需要安装新包并重启插件后生效。

quota.4.12：在左侧栏底部增加 ACP 模型额度面板，分别展示已配置 Antigravity（Gemini）与 Codex 的五小时、周额度剩余比例。点击供应商行刷新，悬停或键盘聚焦查看账号、重置与读取时间；低额度提示、缺报和刷新失败保留明确状态。可见页面每两分钟刷新，复用现有缓存和并发去重，不发送模型请求。

quota.4.13：侧栏供应商名称旁显示实际套餐标签（如 Ultra、Plus），使用额度接口返回的会员信息；未上报套餐时不显示标签，不按供应商写死会员等级。

quota.4.14：侧栏默认以每家供应商一行展示五小时与周剩余额度，悬停或键盘聚焦时展开进度条。摘要、展开面板和悬停提示统一显示最多两位小数，保留真实的零额度与满额度。

## 上游错误终态和无进展恢复提示

- Antigravity 正常返回 `end_turn`，但可见回复仍以其明确的 Google API EOF 或 401 警告结束时，插件保留原始回复并输出错误终态“本轮结果未确认”，不再把协议结束当作任务成功。该检查仅适用于 Antigravity 的已知末尾警告格式；引用、代码块、普通 EOF 解释及错误后继续回复均不直接判失败。其他 Agent、取消及拒绝等原终态不受影响。此规则不保证识别所有上游错误。
- 输入栏新增 ACP 运行状态提示，区分回复接收、等待 Agent、工具执行和待用户授权/回答。当前页面连续两分钟没有可观察的文本或工具进展时提示等待时间；切换会话或轮次重新计时。页面重新打开后从重新观测开始，不声称还原离线期间的状态。
- 取消按钮调用宿主现有取消接口，等待本轮停止后才显示“重连原会话”“新建空白会话”。重连使用原恢复接口，不重发 prompt；新建不复制旧历史。动作受原会话及工作区权限约束，原记录保留。取消不会移除宿主已有排队消息；已有排队工作仍遵循宿主行为。
- 仅提供人工操作，不自动超时中断、不自动重试任务、不修改代理或认证状态。Google 上游 EOF、认证刷新失败和长上下文问题仍需独立排查。

quota.4.16：正常运行不再显示额外状态横条或取消按钮。无可观察进展超过两分钟时，在上下文和速度同一底栏显示“⚠ 暂无新进展”，点击后通过宿主弹窗展开说明和取消操作；进展恢复或进入授权等待后自动收起。已确认的异常显示“本轮异常 · 查看恢复选项”，取消后的恢复入口也收纳为同一行的小按钮。正常完成不保留曾经超时的警告。支持键盘焦点与宿主弹窗关闭行为，窄屏允许底栏自然换行。


## 命令结果自动跟进（quota.4.17）

本地问题记录中，Antigravity 的 `run_command` 启动 `networkQuality` 后仍为执行中，但该轮回复已结束，最终活动被记录为未完成。这说明回复结束不等于命令已经完成；仅凭“请稍候”的文字无法判断后台任务状态。

新逻辑仅匹配当前主会话的结构化 `run_command` 与 `CommandLine` 入参，并使用合并后的工具状态判断。收到正常 `end_turn` 后，若已有命令仍为执行中，最多发送两次内部跟进，要求 Agent 等待并读取同一任务结果，禁止重新执行原命令。跟进结果继续写入同一 DSH 任务，等待期间保留取消能力，跟进文本不重放用户请求。自动跟进会产生额外模型请求。

用户停止、新输入接管、上游取消、认证错误或已识别的 EOF 错误不再跟进。达到上限仍缺少工具终态时，返回 `ACP_COMMAND_RESULT_PENDING`，不伪造任务完成。若 Agent 不上报工具名称、执行状态或原命令终态，自动跟进可能无法触发或仍显示结果未确认；不能仅根据回复文字推定已取得执行结果。

验证使用隔离临时 sidecar 与模拟 ACP runtime，覆盖正常取回、缺失结果上限、终态补丁合并、失败、权限等待、停止、其他运行时、子会话和上游 EOF 等情形。尚未完成真实 Antigravity 会话验收；没有启动浏览器测试，没有覆盖运行中的安装目录。
